# 架构与安全审计

本页保留 v0.2.0 架构说明。v0.3.0 P0 的独立来源覆盖、schema 2、迁移备份和导出空间变化，以 [V030_P0_DESIGN.md](V030_P0_DESIGN.md) 为准。

v0.3.0-preview.1 在上述架构上增加下列路径，未改数据库 schema：

- Material 3 Activity → 有界本地分页查询；UiSignals 只在可见时订阅，更新合并350ms，无轮询。
- 用户刷新 → 独立 SnapshotUserService → 同一固定 ps 白名单 → UID/PID/净化名称 → PackageManager 只读包候选；列表仅驻内存。后台 ProcessBatch 每轮共享一个快照，仍按来源×目标独立验权与入库。
- 默认关闭的手动 NetworkStats 实验 → capability / 用户 Usage Access → 有界只读统计 → UID 组事件。无 VPNService、网络连接或设置写入；禁用/离屏使代次失效，迟到结果不接收。
- 报告半开筛选 → 私有流式 Markdown/JSONL ZIP → 释放数据库锁 → 用户确认的 SAF 位置。记录编号/来源/作用域与时间取整规则随包导出；不保留任意原始文本。
- BoundedCallLane 保持单执行线程与 busy 门禁，增加一个仅供已结束调用交接的有界槽与完成同步，消除完成后立刻再次调用的竞态。未结束（含超时但未响应中断）时仍拒绝所有后续提交，不堆积任务。

这些属于本候选的实现边界；设备验收见 [可见功能验收](V030_VISIBLE_ACCEPTANCE.md)。下面旧版本表中的 schema 1、导出方式等仅是历史说明。

## 数据流

用户界面 → 可见前台服务（specialUse）→ Shizuku Binder → UserService（UID 2000）→ 固定只读命令 → 白名单解析/丢弃原始输出 → 应用私有 SQLite → 用户选择的 JSONL 文件。

Shizuku 是独立安装的授权服务，APK 未嵌入提权器。应用使用 shell 已有可见性，不更改 AppOps、组件状态、系统设置或 SELinux。针对 `specialUse` 声明了 Android 14 权限和用途属性；若未来上架商店，需要按该渠道要求审查用途，不表示已获得商店批准。

## 威胁与处理

- 命令注入：接口不接受字符串命令，固定绝对命令路径，无 shell 解释器；非法 kind/target 拒绝执行。
- 过量输出/挂起：输出上限、进程超时、Binder 等待上限；结果失败不会转换为“没有活动”。
- 授权失效期间的结果：调用前后检查授权/连接代次，暂停/停止标志阻止保存在途结果。被撤权的瞬间可能已有一个只读命令正在执行，最多等其超时/退出；不能承诺跨进程瞬时取消。
- 私密内容：不打开通信/音频文件，无内容采集权限；原始 ps 和 AppOps 输出仅短暂存在于 UserService 内存，不保存。所有证据字符串来自固定原因或白名单解析。
- 静默中断：进程/服务中断、采集失败、调度迟到均有空白期或单来源失败记录。直接杀进程的停止时刻只给区间下界，不伪造准确时间。
- 数据损坏：没有 destructive migration 或升级时删库；未知版本迁移直接报错。写入失败停止采集；原包数据根本不在此包私有目录。
- 数据保密：Android 应用沙箱、禁止备份、不上传。数据库未额外加密，设备被解锁/系统级访问者仍可能读取；导出文件由用户控制。

## 存储预算

主 DB 使用 `max_page_count` 对应 32 MiB；回滚日志模式 TRUNCATE，非 WAL。到约 24 MiB 有效页或 20,000 行时淘汰较旧记录，并持久化 retentionAt。单条 evidence 最多 4096 字符。数据库文件可能保留空闲页并复用，不会每次清理 VACUUM；因此清理后占用不一定马上下降。

回滚日志临时空间与当前写事务有关，通常不超过主库量级；主库与临时日志合计预算约 64 MiB，文件系统开销另计。磁盘不足时不保证还能写入“失败事件”，以通知/界面提示为准。

完整抓包、TLS 明文、流量归因、网络目的地址历史、完整 AppOps 调用审计、受限信息绕过、无空白期保证、隐藏后台保活、云同步、AI 自动控制、原版数据迁移、非 user 0 的完整支持。
