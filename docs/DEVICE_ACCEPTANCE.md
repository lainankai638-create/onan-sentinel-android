# Redmi K40S 实机验收表（尚未执行）

设备必须为 Redmi K40S / Android 14 / HyperOS 1.0.15.0.ULMCNXM。记录 Shizuku 版本、无线调试方式、电池/省电设置、安装 APK SHA-256 和实际签名指纹。禁止卸载旧版、清除旧数据或安装任何同包名测试 APK。

## 启动与采样

1. 记录旧版包名、版本、可见历史条目数量，不改动旧版。
2. 安装 `.preview`，拒绝通知和 Shizuku 时分别检查清晰错误；不应出现成功样本。
3. 允许通知、启动 Shizuku 并授权，启动监控。确认持续通知和暂停/停止入口。
4. 1 分钟间隔观察至少 10 轮。在已授权 adb shell 中分别手动核对：

   ```sh
   adb shell ps -A -w -o UID,PID,NAME
   adb shell cmd appops get --user 0 com.miui.securitycenter
   ```

   这些命令只读，不将完整输出作为应用日志保存。核对采样时间附近的目标 PID 与 AppOps 模式。不存在或受限的目标必须显示未知/不可用，不得报告“正常连续监测”。

## 断线、暂停与持久化

1. 在 Shizuku 管理界面停止服务，记录操作时刻。期望 Binder 回调或下次检查发现，生成空白期；不再写成功采样。
2. 重启 Shizuku。授权仍有效时重新绑定，恢复可用采样并关闭空白期；若需授权，应保持不可用直到用户授权。
3. 从 Shizuku 管理界面撤销本测试包授权，核对无继续采集；重新授权后采样重新建立基线。
4. 暂停 10 分钟：通知保留，无采样增长；恢复后不能将间隔内状态变化描述为连续证据。
5. 手动停止：通知消失、服务退出；重开应用后已有证据仍存在。
6. 仅对 preview 包执行系统设置中的强制停止，然后重开：必须显示异常停止和保守空白期，不能声称准确停止时刻。Android 的强停不允许应用自行恢复。
7. 重启手机：不自动绕过后台启动限制；用户打开并启动后记录之前中断。
8. 导出 JSONL，逐行 JSON 解析，检查无 PID、原始目标包名、归因标签/私密内容；时间向下取整到分钟。历史达到保留阈值后报告应反映 retentionAt。

## 连续 24 小时与耗电

使用默认 5 分钟间隔。时间从用户明确启动算起，实际墙钟至少满 24 小时，不能用加速单元测试替代。

| 项目 | 记录内容 | 验收标准 |
| --- | --- | --- |
| 覆盖 | 起止时刻、每轮时间、成功/失败来源数量、最大样本间隔、空白期 | 任何中断都有记录；不得填补虚构样本 |
| 场景 | 锁屏 ≥8h、正常使用、Wi-Fi 变化、充电/非充电、一次授权断开恢复 | 分别记录条件和结果；保活未达标须明确 |
| 进程 | 各组件观测次数、PID 变化、命令错误 | 目标匹配准确，未知与未观察到分开 |
| 稳定性 | 崩溃/ANR、通知可见性、服务死亡 | 无崩溃/ANR；若系统终止必须显示空白 |
| 存储 | DB 大小、事件数、重开后的末尾记录 | 主库 ≤32 MiB、最多 20,000 条，持久化一致 |
| 耗电 | 监控前后电量/耗电估计，温度、屏幕时长、网络、Shizuku 本身成本 | 与同条件无监控基线比较，报告 mAh 或百分比差，不能预先宣称达标 |

做两轮可比试验：A 为 Shizuku 开启但哨兵停止；B 为同等使用模式下哨兵运行。分别记录 24 小时数据。不要为测量重置用户全局 batterystats；可使用系统电池界面的区间统计或只读 `adb shell dumpsys batterystats cn.onan.sentinel.preview`，将原始设备日志保存在用户受控位置并在分享前审阅。

没有稳定基线时只报告原始测量和条件，不给出“低功耗已通过”。FGS/Doze 可用性与耗电之间有取舍，本版本未持有永久唤醒锁。
