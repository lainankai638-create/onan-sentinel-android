| 场景 | 记录与通过条件 |
| --- | --- |
| 同签名升级 | 先停止 v0.2.0，记录包/版本/签名、events/meta 内容与数量；升级后确认 schema 2、旧值/ID 一致、私有备份存在；迁移和随后保留淘汰分别核对 |
| 空间不足/迁移失败 | 仅专用测试环境制造；应显示 MIGRATION_SPACE_REQUIRED 或具体存储错误，不建立空库；恢复空间后能重试；真实磁盘写满与掉电尚未测 |
| 断连/重连 | 停止 Shizuku→各来源进入空白→重新启动授权→新代次绑定→每个来源成功后分别关闭空白；迟到结果不得成为成功证据 |
| 撤权/暂停 | 在运行及暂停状态撤权；授权、Binder、UserService状态分开显示；无成功采样新增；恢复必须重新验证权限 |
| 单一来源失败 | 用专用假探针/测试输出制造 AppOps 不可用，不能修改系统组件 AppOps；进程恢复不能关闭 AppOps gap |
| 线程/超时 | 重复 100 次超时、暂停/恢复、断连；记录探针线程数和队列，应用进程最多两个调用通道工作线程，不积累任务；与应用其他线程区分 |
| 通知/生命周期 | 通知权限拒绝、渠道禁用、用户停止、系统强停、手机重启；有明确信息与未知区间，不自动绕过后台限制启动 |
| 导出 | 导出大保留历史、取消/提供商失败、导出期间采样；数据库不受外部写阻塞，无全表内存副本，临时文件可清理；核对脱敏 |
| 备份删除 | 仅核对升级后历史并停止监控后明确删除；不影响当前库或原应用；清理当前历史不会自动清理迁移备份 |
