# v0.3.0 P0 设计与范围

基线 `0a4b12fca2a23c56564ed6134a2c1f805e69afad`。需求来源为用户提供的 2026-11-18 后续路线图及其明确选择“开始 v0.3.0 P0 改造”。原 HTML 的上游研究和用户反馈只作为输入资料，没有复制上游实现，也没有将研究声明当作本次实测。本文仅覆盖 R03-01、R03-02、R03-04 的基础实现，以及 R03-08 的验证准备；不代表所有退出门槛已通过。

## 会话与调用

`BindingEpoch` 为每次绑定分配不可复用的令牌，`ServiceConnection` 每次新建，回调同时校验连接对象和令牌。释放先清空引用、提升代次，再解除绑定。`lease` 原子取得 Binder/代次，写入前再次检查代次、Binder 存活与当前授权。`ShizukuApi` 是同一平台调用的窄适配层，测试用假服务不执行任何提权操作。

`CollectionControl` 串行化暂停/停止与一次写入的接受边界。已经开始接受的短本地事务可能先完成，再处理停止；不能声称跨进程撤权能撤回已执行的命令。提交前检测失效则拒绝成功结果。Binder 死亡与权限变化是观察时刻，不伪称系统真实变化瞬间。

`BoundedCallLane` 的线程池无排队，进程和 AppOps 各最多一个工作线程，全应用进程共享。7 秒等待超时只取消等待；调用若忽略中断，通道保持 busy，不创建替代线程堆积任务。进程销毁时线程终止。超时触发旧 UserService 释放/代次作废；重新绑定有指数退避。慢源可能使一次采样等待最长 7 秒或令共享 UserService 重新绑定，因此不承诺另一来源完全无延迟；但不会无限等待或无限排队。

Service 拥有者 token 持久化，延迟退出的旧 Service 不能关闭新 Service 的数据库会话。onDestroy 在主生命周期阶段释放旧连接，避免稍后解绑误伤替代会话。

## 来源覆盖

固定六个 source×target 组合，每个独立保存 status、reason、last_success、last_attempt、open_gap_id。成功的空进程/空操作结果是有效样本；受限、超时、格式未知不是零值。`PARTIAL` 表示可用的局部证据，不表示全量可见。

空白期起点类型：KNOWN_STOP（用户/服务已知停止时刻）、OBSERVED_UNAVAILABLE（首次开始等待样本）、UNKNOWN_LOWER_BOUND（最后成功或更早保守下界）。前者也只能描述本应用停止，不能推断目标停止。每个来源恢复只关闭自己的空白期；只有没有开放来源空白期时，全局兼容字段才允许关闭。

旧全局 GAP 事件保持原样。来源表不能回填旧版本未采集的覆盖率。collection_runs 保存会话、连接代次、开始结束、状态与净化原因；报告仅统计保留的记录，标记时钟倒退。内存基线在暂停、不可用、换连接和恢复后重建，不跨空白猜测变化。

## schema 1→2

`SQLiteOpenHelper` 的升级事务中先核对旧表列、版本与 quick_check，在同一一致读取视图下复制 events/meta/sqlite_sequence 到私有 schema 1 逻辑备份；逐字段带类型、长度的 SHA-256 摘要比对，完整性检查、同步文件后原子改名。保留 AUTOINCREMENT 高水位，避免删除过的旧 ID 被重用。备份不是逐字节复制原 SQLite 文件，用户记录和元数据的值必须一致。

备份完整后只新增 schema_history、source_state、source_gaps、collection_runs、retention_log 及索引；原 events/meta 不 UPDATE/DROP。新事务失败由 SQLite 回滚。已存在备份只在内容一致时复用，否则报错，不覆盖。未知版本/列形状拒绝迁移。正式备份默认保留；临时失败备份可清除，原库永不因错误删除。

主库仍受 32 MiB 限制；已经占满可分配页而无法增加 schema 时应升级失败，不为了成功升级先删旧行。迁移后的采样与异常会话恢复会继续原容量保留策略，清理记账不是永久历史归档。备份、日志与导出临时文件额外占空间。

## 导出

SQLite 游标逐行生成本地脱敏 JSONL 快照，再分块写到外部 Writer；不保留全表对象列表。外部提供商阻塞时数据库锁已释放，本地生成快照仍占用短暂数据库锁和磁盘，性能需设备验证。报表含旧事件来源标记、独立空白区间、保留范围内统计和清理摘要；相对原版增加内容但未实现 R03-06 的范围选择/Markdown。

PID/包名与精确墙钟时间沿用脱敏，临时文件本身也已脱敏。导出失败不会改写原库，进程重启清理自己遗留的临时快照。报告统计不是事件捕获率，日志截断/保留淘汰后的缺失不可补零。
